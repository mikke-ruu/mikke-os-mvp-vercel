# MarketNote Implementation Spec 09: Payment Methods

MarketNoteの支払い方法管理ページ仕様です。

## 目的

出店予定の支払い情報や収支ページで使う支払い方法を、設定画面から管理できるようにする。

- 支払い方法候補をユーザーが自分用に調整できるようにする
- 出店予定追加、出店予定詳細、収支ページで同じ候補を使えるようにする
- よく使う支払い方法を分かりやすく表示する
- 将来的にDESK収支、Order、Fund、Session、Academyにも展開できる支払い方法管理の土台にする

## ルート

```text
/settings/payment-methods
```

設定トップの `支払い方法` 行から遷移する。

## 初期支払い方法

- 現金
- QR
- カード
- ポイント
- 振込
- その他

## データ構造

MVPではDB変更せず、フロント側の保存から始める。

想定構造:

```text

name
is_default
is_active
is_favorite
sort_order
```

将来的にはユーザー単位の設定としてDB保存する。

候補テーブル案:

```text
market_payment_methods
- id
- user_id
- name
- is_default
- is_active
- is_favorite
- sort_order
- created_at
- updated_at
```

## MVP操作

- 支払い方法一覧表示
- 支払い方法追加
- 支払い方法名編集
- 支払い方法非表示
- 非表示支払い方法の復帰
- よく使う支払い方法の設定
- 上へ / 下への矢印移動による並び替え
- 保存
- 保存後、出店予定追加、出店予定詳細、収支ページなど、支払い方法候補を使う画面に反映する

MVP実装時点で全画面への即時接続が難しい場合も、この設定を候補の正とする前提で実装する。

## 削除と非表示の方針

MVPでは支払い方法の完全削除は行わない。

理由:

- 過去の出店予定や収支データとの整合性を守るため
- すでに使われた支払い方法を消すと、過去データや集計の見え方が分かりにくくなるため

使わなくなった支払い方法は `非表示` として扱う。

将来的には以下を検討する。

- 未使用の支払い方法のみ削除可能にする
- 使用済みの支払い方法は非表示のみ許可する
- 削除前に、該当支払い方法を使った出店予定や収支レコード数を表示する

## 支払い方法名変更時の注意

現在のMVP実装では、出店予定や収支レコード側にも支払い方法の文字列を保存する可能性があるため、既存レコードの文字列が自動で一括変更されるとは限らない。

ただし将来的に支払い方法ID連携や支払い方法別集計を強化する場合、支払い方法名変更が過去データや集計の見え方に影響する可能性がある。

そのためMVPでも、支払い方法名変更時には以下の警告を表示する。

```text
支払い方法名を変更すると、今後の入力候補に反映されます。

過去のデータや集計との見え方が変わる可能性があるため、意味が変わる場合は新しい支払い方法を追加してください。

変更してもよろしいですか？
```

ボタン:

- キャンセル
- 変更する

使用済み判定ができるようになったら、使用済みの支払い方法のみ警告する。
MVPでは、支払い方法名変更時に編集セッション内の初回変更で警告する。

## 並び替え

支払い方法は一覧内で並び替えできる。

- ドラッグではなく、上へ / 下への矢印移動で行う
- 一番上の支払い方法は上へ移動できない
- 一番下の支払い方法は下へ移動できない
- 保存後、候補表示順にも同じ順番で反映する
- よく使う支払い方法は表示上の目印であり、並び順を自動で変えない
- 操作アイコンが増えすぎないよう、D案の軽いUIに合わせる

## UI方針

Mikke OS Design SystemとMarketNote D案に合わせる。

- 収支カテゴリ管理と近い操作感
- 白ベース
- 細線
- 軽いカード
- 弱い影
- オレンジアクセント
- グリーン補助
- ニュートラルグレー
- スマホで見やすい余白と行高
- 入力欄は軽く
- 押せるものは押せる見た目にする
- 押せないものは押せそうに見せない
- 未実装アイコンは出さない

アイコンが増えすぎて見づらくならないように、各行の主操作は以下に絞る。

- よく使う切り替え
- 上へ
- 下へ
- 編集
- 非表示

非表示中の支払い方法では、復帰を主操作にする。

## 候補利用画面との接続

支払い方法候補を使う画面は、この設定を参照する。

対象:

- 出店予定追加
- 出店予定詳細
- 収支ページ
- 今後の収支入力モーダルやDESK収支

MVPでは以下でよい。

- 設定ページで保存
- 対象画面を開いた時に保存済み支払い方法を読み込む
- 非表示の支払い方法は候補に出さない
- 並び順は `sort_order` を使う
- よく使うフラグでは候補順を自動変更しない
- 既存レコードの表示は、保存済み候補に存在しない名前でも壊さず表示する

## 保存方針

MVPでは収支カテゴリ管理と同じ保存方針にする。

- 編集中はローカル状態で保持する
- `保存` でまとめて確定する
- 保存後に候補利用画面へ反映する
- 保存前に離脱する場合は、未保存変更があることを分かるようにする
- 初期支払い方法に戻す場合は確認を出す

## バリデーション

- 支払い方法名は空にできない
- 前後の余白は保存時に取り除く
- 表示中、非表示を含めて同名は追加しない
- 長すぎる名前はスマホ表示で崩れないようにする
- 非表示にしても、過去データの表示には使えるようにする
