# MarketNote Implementation Spec 10: Reminders

MarketNoteの通知 / リマインダー設定ページ仕様です。

## 目的

MarketNoteの出店予定に対して、支払い・準備・提出物・当日確認などの通知 / リマインダー設定を管理できるようにする。

- 出店前に見落としやすい支払い、準備、提出物、当日確認を期限順に扱えるようにする
- ホームの「やること（期限順）」や出店詳細のチェック項目と接続する
- 実通知を入れる前に、通知対象・通知タイミング・通知時間を保存できる土台を作る
- 将来的にプッシュ通知、メール通知、LINE通知へ拡張できる設定構造にする

## ルート

```text
/settings/reminders
```

設定トップの `通知 / リマインダー` 行から遷移する。

## MVPで実装する範囲

- 通知 / リマインダー設定ページを追加
- 通知を使う / 使わない のON/OFF
- 通知対象の設定
  - 支払い期限
  - チェック項目の期限
  - 出店日前日
  - 出店当日
- 通知タイミングの設定
  - 当日
  - 1日前
  - 3日前
  - 7日前
- 通知時間の設定
  - 9:00
  - 12:00
  - 18:00
  - 21:00
- ホームの「やること」や期限順表示との接続方針を表示
- 保存
- 初期設定に戻す

MVPでは実際のプッシュ通知、メール通知、LINE通知は行わない。
設定内容を保存し、ホームの「やること（期限順）」や期限管理に反映できる状態を作る。

## 実通知未実装の扱い

MVPでは、画面内に以下の説明を表示する。

```text
通知機能は今後対応予定です。
現在はホームのやること表示と期限管理に反映されます。
```

重要ルール:

- 実通知が送られるように見せない
- 押せない通知ボタンや未実装アイコンは出さない
- 「プッシュ通知を許可」「メール通知を送る」「LINE通知を送る」のような未実装操作は表示しない
- 保存できるのは、今後の通知とホーム表示に使う設定であることを明示する

## 初期設定

MVPの初期値:

```text
enabled: true
targets:
  payment_due: true
  check_item_due: true
  event_previous_day: true
  event_day: true
timings:
  same_day: true
  one_day_before: true
  three_days_before: false
  seven_days_before: false
time: "09:00"
```

初期表示では、最小限のリマインドが働く前提にする。

- 支払い期限
- チェック項目の期限
- 出店日前日
- 出店当日

をONにする。

## UI方針

Mikke OS Design SystemとMarketNote D案に合わせる。

- 収支カテゴリ管理 / 支払い方法管理と近い操作感
- 白ベース
- 細線
- 軽いカード
- 弱い影
- オレンジアクセント
- グリーン補助
- ニュートラルグレー
- スマホで見やすい余白と行高
- 設定項目はカードで整理する
- ON/OFFや選択肢は分かりやすくする
- 押せるものは押せる見た目にする
- 押せないものは押せそうに見せない
- 未実装アイコンは出さない

ON/OFFはトグル表示でよい。
通知対象と通知タイミングはチェックボックスまたは押せる行で切り替える。
通知時間はセグメントボタンで選択する。

## 保存方針

MVPでは、設定ページ内のローカル状態を `保存` で確定する。

- 編集中はローカル状態で保持する
- `保存` でまとめて確定する
- 保存後にホームの「やること（期限順）」や期限管理へ反映する前提にする
- 保存前に離脱する場合は、未保存変更があることを分かるようにする
- `初期設定に戻す` は確認を出してから実行する

## ホームのやること表示との接続

ホームの「やること（期限順）」は、以下をもとに表示する。

- 出店予定の日付
- チェック項目の `due_date`
- チェックテンプレートの `due_rule`
- 支払いステータス
- リマインダー設定の `enabled`
- リマインダー設定の通知対象
- リマインダー設定の通知タイミング

MVPでは、実通知ではなくホーム表示の優先度や表示対象に使う。

例:

- `enabled = false` の場合、ホームの通常表示は維持しつつ、リマインダー強調はしない
- `payment_due = true` の場合、未払いの支払い情報をやることに出せるようにする
- `check_item_due = true` の場合、期限付きチェック項目をやることに出せるようにする
- `event_previous_day = true` の場合、出店日前日に当日準備の確認を出せるようにする
- `event_day = true` の場合、出店当日に当日確認を出せるようにする

## チェックテンプレートとの接続

チェックテンプレート管理では、各チェック項目に期限ルールを持つ。

既存の期限ルール:

- 開催日当日
- 開催日前日
- 開催日の3日前
- 開催日の7日前
- 期限なし

リマインダー設定は、この期限ルールから算出される `due_date` を通知・やること表示の基準にする。

MVPでは以下でよい。

- チェックテンプレートの `due_rule` をもとに、出店予定作成時または表示時に仮の期限を計算する
- `期限なし` の場合は、ホームで強調しない
- 期限が未保存の場合は、出店日を仮期限として扱う
- リマインダー設定がOFFでもチェック項目自体は消さない

## 出店詳細ページとの接続

出店詳細ページでは、チェック項目と支払い情報を確認・更新できる。

MVPでは以下でよい。

- 出店詳細のチェック項目に期限がある場合、期限表示の追加を後続で検討する
- 支払いステータスが未払いの場合、リマインダー対象にできるようにする
- 出店日前日 / 出店当日の確認項目は、詳細ページのチェック項目やメモと接続する
- 実通知が未実装であることは、設定ページ側で明示する

## 通知対象

### 支払い期限

対象:

- 出店料など、支払い情報が未払いの出店予定
- 支払い金額があり、支払いステータスが `未払い` のもの

MVPでは支払い期限の専用日付がない場合、出店日またはチェック項目の期限を仮期限にする。
将来的には支払い期限日を入力できるようにする。

### チェック項目の期限

対象:

- チェックテンプレートから作成されたチェック項目
- 出店詳細で追加されたチェック項目
- `due_date` または `due_rule` から期限が分かるもの

### 出店日前日

対象:

- 出店日の1日前
- 持ち物、搬入時間、ブース位置、告知、決済準備などの確認

### 出店当日

対象:

- 出店日当日
- 集合時間、搬入、支払い状況、チェック未完了項目などの確認

## 通知タイミング

通知タイミングは、対象の基準日から何日前にホームのやることへ出すかを決める。

- 当日
- 1日前
- 3日前
- 7日前

複数選択できる。
MVPでは、実通知送信時刻ではなく、やること表示の対象範囲や強調に使う。

## 通知時間

通知時間は1つ選択する。

- 9:00
- 12:00
- 18:00
- 21:00

MVPでは実通知を送らないため、保存のみ行う。
将来的にプッシュ通知、メール通知、LINE通知の送信時刻として使う。
