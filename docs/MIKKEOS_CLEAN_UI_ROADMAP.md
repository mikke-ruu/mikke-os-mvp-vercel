# mikkeOS Clean UI Roadmap

作成日: 2026-07-11

このdocsは、mikkeOS全体の見た目を、Storyで見えてきた「すっきり・読みやすい・余白がきれい」な方向へ揃えるための計画です。

目指す方向は、Appleのように余白、文字、配置が整っていて、触る前から安心できるUIです。ただしAppleそのものを真似るのではなく、mikkeOSらしいやわらかさと事業管理の使いやすさを両立します。

## 1. 目指す見え方

```text
白ベース
細い線
軽い影
読みやすい文字
広めの余白
整ったアイコン
8px前後の角丸
カードを重ねすぎない
色を使いすぎない
説明しすぎない
スマホで見ても詰まらない
```

今のStoryを、mikkeOS共通UIの基準にします。

Storyでよかった点:

- 上部がすっきりしている。
- 文字の大きさに強弱がある。
- 余白があり、詰まって見えない。
- アイコンとテキストの関係がわかりやすい。
- カードが軽い。
- アプリ入口や管理メニューが整理されている。
- スマホで見た時に、名刺として見せやすい。

## 2. 直したい現在の課題

現在のmikkeOS内には、画面ごとに見え方の差があります。

課題:

- アプリごとに余白が違う。
- カードの角丸、線、影が違う。
- ヘッダーや戻る導線が画面ごとに違う。
- 説明文が多く、重く見える画面がある。
- 色が画面ごとにばらつく。
- 文字化けや仮文言が残っている。
- Storyだけ新しいUIで、他のアプリが古い印象に見える。
- アプリ間を行き来する導線がまだ統一されていない。

## 3. 共通デザイン原則

### 3.1 余白

余白は詰めすぎない。

基本:

```text
画面左右: 16px
セクション間: 20-28px
カード内: 12-16px
リスト行: 12px前後
ボタン内: 10-14px
```

情報量が多い画面でも、カードを詰め込まず、まとまりごとに余白を取ります。

### 3.2 文字

文字は、読みやすさを最優先にします。

基本:

```text
画面タイトル: 20-24px
セクション見出し: 16px
カードタイトル: 14-16px
本文: 14px
補足: 12-13px
タブ / ナビ: 11-12px
```

注意:

- 画面幅に合わせて文字を極端に拡大しない。
- 日本語が詰まって見えないように行間を取る。
- 長い説明はカード内に詰めず、必要な場所だけに置く。
- 画面内の太字を増やしすぎない。

### 3.3 色

色は少なくします。

基本:

```text
背景: 白またはごく薄いグレー
本文: 濃いネイビー / 黒に近いグレー
補足: グレー
線: 薄いグレー
アクセント: mikkeOSの主色を1色
成功: グリーン
注意: オレンジ
危険: レッド
```

色は装飾ではなく、状態や操作の意味を伝えるために使います。

### 3.4 角丸

角丸は丸くしすぎません。

```text
基本カード: 8px
小ボタン: 8px
入力欄: 8px
大きなパネル: 10-12px
丸いアイコン背景: 必要な時だけ
```

ふわふわしすぎるUIではなく、すっきりした道具感を保ちます。

### 3.5 影

影は弱くします。

基本:

- 影だけで浮かせない。
- 細い線を主に使う。
- 影は重要なパネルやメニューだけ。
- 何重にもカードを重ねない。

### 3.6 アイコン

アイコンはlucideを基本にします。

方針:

- ボタンにはできるだけアイコンを入れる。
- アイコンだけのボタンには `aria-label` を付ける。
- 意味がわからないアイコンは、テキストとセットにする。
- 手描きSVGを増やさない。

## 5. 共通ナビゲーション

各アプリから、同じ操作感で移動できるようにします。

必要な導線:

```text
OS Home
Story
DESK
Log
Apps
持っているアプリ
管理画面
まだ繋げていないアプリの提案
```

Storyで追加したハンバーガーメニューを、将来的にはOS共通の本人用メニューにします。

方針:

- 公開ページに見せる内容と、本人用の管理導線を分ける。
- ログイン中の本人には、持っているアプリだけを出す。
- 持っていないアプリは「繋げますか」と自然に提案する。
- 各アプリの右上メニューを同じ形にする。

## 6. Storyを基準にする理由

Storyは外に見せる名刺ページです。

そのため、mikkeOSの中でも一番「人に見せて恥ずかしくない見た目」が必要です。

Storyを基準にすることで、他のアプリも以下の方向へ揃えられます。

- 見た目が軽くなる。
- 説明しすぎない。
- 操作が見つけやすい。
- スマホで読みやすい。
- ビジネスにもクリエイターにも合う。

## 7. 画面ごとの移行方針

### Phase UI-0: 文字化けと古い文言の確認

最初に、画面上で見える文字化けや古い仮文言を確認します。

対象:

```text
/os
/log
/desk
/apps
/apps/*
/marketnote
/settings
Team Works
Academy
```

方針:

- ユーザーに見える文字化けを優先して直す。
- Activity Log公開タイムライン前提の古い表現を直す。
- Story / DESK / OS Homeの意味を混同しない。

### Phase UI-1: 共通デザイントークンを整理

共通の色、余白、角丸、文字サイズを決めます。

対象:

```text
app/globals.css
components/mikkeos/*
```

やること:

- CSS変数を整理する。
- カード、線、背景、文字色の基準を作る。
- Storyの見た目に近い標準値へ寄せる。

### Phase UI-2: 共通部品を作る

まずは小さく始めます。

最初に作る候補:

```text
MikkeSection
MikkeActionCard
MikkeListRow
MikkeOwnerMenu
MikkeStatusBadge
```

目的:

- 各アプリが同じ見た目を使えるようにする。
- 画面ごとのバラつきを減らす。
- 後からテンプレートやテーマに対応しやすくする。

### Phase UI-3: `/apps/*` を統一

最初の置き換え対象は `/apps/*` がよいです。

理由:

- 影響範囲が小さい。
- アプリ入口として全体の印象に効く。
- Item Studio / Order / Session / Academy / Community などをまとめて揃えやすい。
- Storyで作った持っているアプリ導線と相性がよい。

対象:

```text
/apps
/apps/item-studio
/apps/order
/apps/session
/apps/academy
/apps/community
/apps/event
/apps/market-note
/apps/team-works
```

### Phase UI-4: OS Home / Log / DESK を統一

次に、OSの中心画面を揃えます。

対象:

```text
/os
/log
/desk
```

方針:

- `/os` は管制塔として軽く見せる。
- `/log` は管理用なので、一覧性を優先する。
- `/desk` は数字が見やすいことを優先する。
- すべてStoryと同じ余白・線・角丸のルールで揃える。

### Phase UI-5: MarketNote / Team Works / Academy本体へ展開

機能が多いアプリは、共通部品ができてから移行します。

対象:

```text
MarketNote
Team Works
Academy
Community
```

注意:

- 一気に全部作り替えない。
- まずヘッダー、カード、一覧、詳細だけ揃える。
- 保存処理やDB接続はこのUI整理では触らない。

### Phase UI-6: Storyカスタムとテンプレート

Storyの管理画面で、見た目を変えられるようにします。

対象:

```text
背景色
背景画像
アクセントカラー
文字サイズ
テンプレート
無料テンプレート
有料テンプレート
ビジネス向け
クリエイター向け
講師向け
ショップ向け
```

これは後半で行います。

まずはmikkeOS全体の基本UIを揃えることを優先します。

## 8. 今すぐやらないこと

```text
全画面の一括リデザイン
全アプリの保存処理変更
Supabase本接続
DBマイグレーション
RLS / policy / constraint変更
有料テンプレート課金
背景画像アップロード
テーマ販売
```

UIの見た目整理と、データ接続の変更は分けて進めます。

## 9. 推奨する次の作業

次は、以下の順番を推奨します。

```text
1. Storyを基準にした共通UI部品を作る
2. /apps と /apps/* の見た目を揃える
3. OS Home / Log / DESK を揃える
4. MarketNote / Team Works / Academy本体に広げる
5. Story管理画面でテーマ・テンプレートを扱う
```

最初の実装対象は `/apps` と `/apps/*` が安全です。

Storyはすでに方向性が見えています。次は、アプリ入口の見た目を揃えることで「mikkeOS全体が同じ空気の中にある」状態を作ります。

## 10. 完了の目安

UI統一がうまくいっている状態:

- どのアプリを開いても、同じOSの中にいると感じる。
- 文字が読みやすい。
- 余白が詰まっていない。
- 操作ボタンが迷子にならない。
- 管理画面っぽく重く見えない。
- スマホで見ても崩れない。
- Story / DESK / Apps / OS Home の移動が自然。
- 余計な説明がなくても、何をすればよいかわかる。
