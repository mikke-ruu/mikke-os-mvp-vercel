# mikke AI OFFICE — MVP実装ブリーフ（Sonnet向け）

作成: 2026-07-18（Fableが骨格を作成、Sonnetが UI 本体を実装する分担）

## 概要

AI社員と人間が一緒に働く「バーチャルオフィス」を可視化する独立アプリ。
ドット絵（ピクセルアート）風のかわいいオフィス画面の中で、案件が
受付 → 作業中 → 確認待ち → 完了 と流れる様子が見える。

- ルート: `/apps/ai-office`（`app/apps/ai-office/page.tsx`、実装済み・変更不要のはず）
- API接続なし。localStorage保存（`lib/ai-office/store.ts` 実装済み）
- 認証なし。AuthGate / MikkeAppShell は使わない（独立フルスクリーン画面）

## 骨格（実装済み・原則変更しない）

- `lib/ai-office/types.ts` — 型定義
- `lib/ai-office/data.ts` — 部屋・社員・初期案件・ラベル・`roomForCase()`（案件→部屋のルール）
- `lib/ai-office/store.ts` — `useOfficeStore()`（localStorage、案件追加/状態変更/担当変更/ログ）
- `lib/ai-office/agent-runtime.ts` — `executeAgentTask()` mock実行レイヤー
- `app/apps/ai-office/page.tsx` — 画面合成（props契約はここが正）

## Sonnetの作業対象（`components/ai-office/` の7ファイルを本実装に置き換える）

各ファイルの props は現在のスタブと同一に保つこと（page.tsx と契約済み）。

1. `OfficeSidebar.tsx`
2. `OfficeFloor.tsx` ← 最重要・一番手をかける
3. `CaseBoard.tsx`
4. `WorkloadMonitor.tsx`
5. `ActivityLogPanel.tsx`
6. `QuickActions.tsx`
7. `NewCaseModal.tsx`

必要なら `components/ai-office/` 内にサブコンポーネント（例: `PixelEmployee.tsx`、`PixelRoom.tsx`）を追加してよい。

## デザイントーン

- 白背景ベース（`#f6f7fb` 地に白カード）。補助色はネイビー `#1e2a4a`、オレンジ `#e58f65`、淡いグレー
- オフィスフロアだけは木目の温かい空間（茶系・ドット絵）。UI全体は見やすい管理画面
- 「楽しいのに仕事で使えそう」。ゲームUI寄りすぎず、実務アプリ寄りすぎず
- 角丸カード `rounded-2xl`、border `#e3e6f0`、影は控えめ
- lucide-react のアイコン使用可（依存済み）。**新しいnpmパッケージは追加しない**
- 画像ファイルは使わない。ドット絵はインラインSVGで描く

## オフィスフロア（OfficeFloor）の要件

参考モック構図: 上段4部屋（受付・社長室 / 顧問室 / 講座制作室 / 編集室）、
下段4部屋（デザイン室 / 実装室 / 会議室 / 休憩室）、最下部に細長い「みっけテラス」帯（植物・犬など）。

- 部屋データは `rooms`（data.ts）を使う。2行×4列のグリッドでOK（モバイルは2列に折り返し）
- 各部屋:
  - 上部にネイビーの看板風の部屋名ラベル
  - 木目床（茶系のドット/ストライプ表現）＋壁
  - 小物をSVGで: 机、PC、本棚、観葉植物、会議机、コーヒーメーカーなど部屋ごとに変える
  - その部屋がホームの社員（`employees` の `homeRoomId`）をドット絵キャラで表示
  - 名前＋役割の小ラベル（白地に角丸の吹き出し風）
- ドット絵キャラ: インラインSVGで 12×14 ピクセル程度のグリッドを `<rect>` で描く。
  `shape-rendering="crispEdges"` を指定。社員ごとに `employee.color` を服の色に使う。
  AI社員は頭にアンテナや「AI」バッジなど、人間と見分けがつく小さな差をつける
- 社員の状態表示:
  - その社員に `status: "reception" | "working" | "review"` の案件があれば「稼働中」（緑ドット等）
  - `homeRoomId === "break"` は「休憩中」
  - それ以外は「待機中」
- 案件の可視化: `roomForCase(c)`（data.tsのルール）で、未完了案件がある部屋に
  小さな案件バッジ（件数）や書類アイコンを表示。案件が動くと部屋の表示が変わること
- 稼働中の社員にCSSアニメーション（ぴょこぴょこ上下 2px 程度、`animation` で）を付けると楽しい
- たまに吹き出し（「作業中…」「コーヒーでひと息」等）が出るのは任意（できれば）

## 案件ボード(CaseBoard)

- 4列カンバン: 受付（青系）/ 作業中（オレンジ系）/ 確認待ち（黄系）/ 完了（緑系）。列ヘッダに件数
- カード: 案件名 / 担当（名前＋小さな丸アイコン）/ 優先度バッジ / 更新時刻（`updatedAt` をHH:mm表示）/ 関連チーム
- カード上で: ステータス変更（selectか矢印ボタン）と担当変更（select）ができる
- 「＋新規案件」ボタンで `onNewCase()`

## 稼働モニター(WorkloadMonitor)

- 部屋（講座制作室 / 編集室 / デザイン室 / 実装室 / サポート）ごとにバー表示
- 数値は「ベース値＋その部屋の未完了案件数×15%」等の簡易計算でよい（上限95%）
- 案件0の部屋は「待機中」表示、それ以外は「稼働中」

## アクティビティログ(ActivityLogPanel)

- `logs` を上から新しい順に8〜10件。時刻 / 社員のドット風ミニアイコン（色丸でよい）/ 名前 / メッセージ
- 「すべて見る」は見た目だけでよい（クリックで全件表示に切り替わればなお良い）

## サイドバー(OfficeSidebar)

- 上: アプリアイコン（ドット絵風の小さな猫/クマ顔SVGなど）+ `mikke AI OFFICE` + 緑ドット「オンライン: {onlineCount}名」
- ナビ: オフィスフロア（選択中）/ 案件ボード / 稼働モニター / コミュニケーション / ナレッジベース / 設定（lucideアイコン付き。遷移はしなくてよい、見た目のみ）
- チーム・スペース: `teamSpaces`（data.ts）
- 下: 「mikkeOSと同期中」カード（ダミー）
- モバイル（lg未満）では非表示のままでよい

## クイックアクション(QuickActions)・モーダル(NewCaseModal)

- QuickActions: 現スタブの3ボタンを見た目良く。「案件を新規作成」はオレンジの主ボタン
- NewCaseModal: 現スタブのフォーム項目そのまま、見た目を整える（ラベル付き、角丸、フォーカスリング）。
  Escや背景クリックで閉じる。件名未入力なら作成ボタンをdisabled

## 完了条件（フェーズ1・達成済み 2026-07-18）

1. `npm run lint`（= `tsc --noEmit`）が通る（既存の別アプリ由来のエラーは無視してよい。ai-office関連のエラー0）
2. `/apps/ai-office` が表示され、初期ダミー案件4件・社員8人・ログ5件が見える
3. 新規案件を作成 → 受付列に入り、ログが増え、AI社員の返事ログ（mock）が流れる
4. ステータスを変更 → ボードとオフィスフロアの両方が変わり、localStorageに保持される（リロードで残る）
5. 見た目がかわいい（ドット絵の部屋・キャラがちゃんと描かれている）

# フェーズ2 — オフィスフロア世界観リニューアル（2026-07-18）

フェーズ1のフィードバック: 機能とフローは良いが、部屋が均等カードで並び
「ドット絵付き業務ダッシュボード」に見える。「小さな仲間が働いている会社」感を強める。

**今回のスコープはオフィスフロアのみ。** 案件ボード・稼働モニター・ログ・モーダル・
サイドバー・page.tsx・lib/ai-office/ は触らない。

## 変更対象ファイル

- `components/ai-office/OfficeFloor.tsx` — 全面作り直し
- `components/ai-office/PixelRoom.tsx` — 削除または全面置き換え（新構造に合わせて自由）
- `components/ai-office/pixel-sprites.tsx` — キャラ拡大・家具追加
- `components/ai-office/office-helpers.ts` — `roomForEmployee()` 追加（下記）
- `app/globals.css` — ai-office系keyframesの追加・調整（既存ルールは触らない）
- 新規サブコンポーネントの追加は `components/ai-office/` 内で自由

`OfficeFloor` の props（`{ cases, hydrated }`）は変更しない。

## 1. 建物を一枚につなげる

部屋ごとの独立カードをやめ、**フロア全体を1つの大きなインラインSVG**として描く。

- 推奨構造: `viewBox="0 0 1600 620"` 程度の1枚のSVG（レスポンシブは `width:100%` で縮小、
  モバイルは横スクロール可の `overflow-x-auto` コンテナに入れる）
- 建物全体を囲む外壁（濃い茶＋屋根ライン）
- 上下2列の部屋の間に**横方向の廊下**（明るい床材）。廊下に各部屋への**ドア開口部**
- 左端または中央下に**エントランス**（マット・受付ベル）
- 下端に**みっけテラスへの出口**（廊下から階段/ドア）
- 名前ラベル・吹き出し・案件バッジ・ツールチップはSVGの上に絶対配置のHTMLオーバーレイでよい
  （座標はviewBoxとの比率で合わせる）

## 2. 部屋の広さ・形に変化をつける

均等グリッド禁止。目安（合計幅1600の場合）:

- 上段: 受付・社長室 480（広い） / 顧問室 300（小さめ） / 講座制作室 440 / 編集室 380
- 下段: デザイン室 380 / 実装室 380 / 会議室 480（広い） / 休憩室 360
- 部屋の奥行きも上下で少し変えてよい

## 3. 部屋ごとの床色・家具（各部屋3〜5個の特徴物）

部屋全体を強い色で塗らず、**ラグ・壁の一部・椅子・小物**に淡い補助色を使う。床は木目基調を維持。

| 部屋 | 補助色 | 家具・小物 |
|---|---|---|
| 受付・社長室 | クリーム | 受付カウンター、電話、書類、額縁、大きめデスク、観葉植物 |
| 顧問室 | ラベンダー | ソファ、丸テーブル、ティーカップ、本棚、小さな猫、紫ラグ |
| 講座制作室 | ライトブルー | 共同制作机、教材ノート、ホワイトボード、付箋、撮影ライト、講座画面モニター |
| 編集室 | 淡いピンク | 大きな本棚、原稿の山、赤ペン、PC、校正紙、ピンク系ラグ |
| デザイン室 | 淡いコーラル | 液タブ、カラーチャート、ポスター、画像一覧モニター、観葉植物 |
| 実装室 | ブルーグレー | 複数モニター、コード画面、サーバーラック、工具箱、床は少し暗め |
| 会議室 | ライトグリーン | 大きな会議テーブル、椅子、プロジェクター、進捗ボード、飲み物 |
| 休憩室 | ミント | コーヒーマシン、冷蔵庫、ソファ、お菓子、小テーブル、コーヒー湯気 |

## 4. キャラクター強化（1.5〜2倍）

- 現在の12×14グリッドを**16×20程度に増やし、表示スケールも上げる**（フロア内で高さ48〜64px相当）
- 髪型・顔（目・ほっぺ）・服装が判別できること。`employee.color` は服に使う
- AI社員: アンテナ＋小さな光など。ロボットすぎず「一緒に働く仲間」としてかわいく
- 社員ごとに髪型・髪色を変えて個性を出す（data.tsは変更せず、スプライト側でid別にバリエーション）
- ラベル: 通常時は小さな名前ラベルのみ。**ホバーまたはクリックで役割・状態・担当案件をツールチップ表示**。
  作業中だけたまに小さな吹き出し

## 5. 社員の配置と移動感

`office-helpers.ts` に `roomForEmployee(employee, cases)` を追加:

1. その社員に `review` の案件があれば → 会議室
2. `working` の案件があれば → その案件の `roomForCase()` の部屋
3. `reception` の案件があれば → ホームの部屋（待機して待つ）
4. 案件がなく `homeRoomId === "break"` → 休憩室
5. それ以外 → ホームの部屋

社員の描画位置はこの結果で決め、**CSS transition（1〜2s）で座標移動**させて
「廊下を通って移動しているように見える」効果を出す（厳密な経路探索は不要）。

## 6. 状態演出（控えめに・イベント時だけ）

常時全員ぴょこぴょこは廃止。

- 待機中: 静止＋たまに首/目が動く程度（数秒に1回の小さなkeyframe）
- 作業中: PC画面の点滅、たまに小さな吹き出し
- 休憩室: コーヒーの湯気アニメーション
- 完了案件が出たとき・案件バッジ変化時: 小さなキラキラ/チェック（CSSで短く）
- テラス: 猫または鳥がたまに動く

## 7. 案件バッジ

- 部屋の右上に件数バッジ（現行踏襲）
- **バッジをクリックすると、その部屋の案件（タイトル・担当・状態）の小さなポップオーバーが開く**。
  閉じるのは外側クリック。CaseBoardには触らない

## 8. みっけテラス

- 花壇・ベンチ・小さなテーブル・植木・猫か鳥
- 休憩中（案件なしのbreak所属）社員がテラスにいることがある、程度でよい
- オフィスより目立たせない

## 9. フロアを主役に

- フロアSVGの表示高さを現行より大きく（PC表示で画面の60〜70%目安）。
  page.tsxは触らず、OfficeFloor内の高さ/アスペクトで調整する

## フェーズ2完了条件

1. 部屋が独立カードでなく、一つの建物に見える（外壁・廊下・ドア・エントランス）
2. 部屋の広さ・床・家具で役割が判断できる
3. キャラが大きくなり、個性とAI/人間の違いが分かる
4. 社員の位置が案件状態で変わり、transitionで移動して見える
5. バッジクリックで部屋の案件ポップオーバーが開く
6. 案件操作・localStorage・ログ等の既存機能が壊れていない（lib/とpage.tsxは無変更）
7. `npx tsc --noEmit` エラー0、`npm run build` 成功

# フェーズ3 — UI仕上げ＋Claude Code接続の土台（2026-07-18）

## Sonnet A: UI・世界観の仕上げ

### A-1. フロアの密度アップ（部屋ごとに小物を2〜4個追加）

- 受付・社長室: 受付カウンター感を強く。書類・電話・受付ベル。社長席と受付の役割が分かるように

- 編集室: 本棚・原稿の束・校正紙・赤ペンで「文章仕事の部屋」
