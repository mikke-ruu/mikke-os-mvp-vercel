# Fund App Concept

Fundは、Mikke OSの将来アプリ構想です。今すぐ実装するものではなく、Order再構築、DESK Contacts、DESK収支、Story、Item Studioへ派生できるようにするための構想メモとして保存します。

## 1. アプリ名

アプリ名は単体で `Fund` とします。

Mikkeという言葉は、OS / 母体 / 現在の活動名として扱い、各アプリ名には使いません。

使わない名前:

- Mikke Fund
- Mikke Project

使う名前:

```text
Fund
```

## 2. Fundの目的

Fundは、個人や小さな活動者が、自分のプロジェクトごとに応援、支援、予約購入を募れるアプリです。

大きなクラウドファンディングプラットフォームへ出すのではなく、活動者自身が自分のページを作り、必要な金額やリターンを設定し、支援者を募れる仕組みにします。

基本の流れ:

```text
LPビルド式でプロジェクトページを作る
↓
目標金額や募集期間を載せる
↓
応援プラン / リターンを設定する
↓
注文ボタン / 応援ボタンを置く
↓
支援者が申し込む
↓
支援金額と支援者情報を管理する
```

## 3. FundはOrderの派生で作れる可能性が高い

Fundはゼロから作るより、Orderの仕組みを改造・派生させることで早く作れる可能性があります。

OrderとFundは目的は違いますが、裏側の構造が近いです。

Order:

```text
商品・サービスを注文してもらう
```

Fund:

```text
プロジェクトを応援・予約購入・支援してもらう
```

共通する仕組み:

```text
LPを作る
金額を載せる
プランを作る
注文 / 申込ボタンを置く
顧客情報を受け取る
金額を集計する
ステータス管理する
メールや案内を送る
```

FundはOrderとは別アプリとして成立させつつ、内部構造やUI部品はOrderから多く流用できる想定です。

## 4. Orderとの違い

Orderは「依頼・注文を受ける」アプリです。

例:

```text
名刺制作
LP制作
オーダー作品
出店サポート
サービス申込
```

Fundは「企画や活動に対して応援・支援・予約購入を募る」アプリです。

例:

```text
新作制作を応援してほしい
展示会出展費を集めたい
ポップアップ開催資金を募りたい
講座制作を応援してほしい
アトリエ整備費を募りたい
出版や作品集制作を応援してほしい
地域イベント開催費を募りたい
```

ユーザーの目的が違うため、FundはOrder内の一機能ではなく、独立アプリとして扱います。

## 5. Fundで使う言葉

Fundは投資型ではなく、応援購入・予約販売・支援ページ作成アプリとして設計します。

避けたい言葉:

```text
出資
投資
配当
利回り
分配
株
金融商品
```

使いたい言葉:

```text
応援
支援
予約購入
先行販売
リターン
プロジェクト
サポーター
応援プラン
活動報告
```

特に「出資」という言葉は規制や金融商品の印象につながる可能性があるため、基本的には使いません。

## 6. Fund MVP機能

最初のMVPは以下を想定します。

```text
1. プロジェクト作成
2. 公開LP生成
3. 応援プラン / リターン作成
4. 注文 / 支援フォーム
5. 支援者一覧
6. 合計支援額表示
7. 目標金額表示
8. 募集期間表示
9. ステータス管理
```

決済は最初から完全自動でなくてもよいです。

MVP候補:

```text
銀行振込
PayPay
Stripeリンク
手動確認
```

将来的にはStripe決済連携が自然です。

Fundの公開ページはLP形式にします。

```text

現在の支援額
支援人数
募集期間

スケジュール
リターン / 応援プラン
活動報告
応援コメント

```

ページはOrderと同じく、LPビルド式で作れるとよいです。

## 8. 応援プラン / リターン例

ハンドメイド作家、講師、イベント主催者、クリエイター向けに使いやすいリターン例です。

```text
応援だけ 1,000円
お礼メッセージ 3,000円
限定アクセサリー 5,000円
ワークショップ参加券 8,000円
先行予約セット 12,000円
スポンサー掲載 30,000円
制作過程レポート付き応援 5,000円
完成品先行お届け 10,000円
```

リターンなしの純粋な応援と、リターンありの予約購入の両方に対応できるようにします。

## 10. DESK Contactsとの連携

Fundで支援してくれた人は、将来的にDESK Contactsへ集約します。

FundからDESK Contactsへ送る情報:

```text
支援者名
メールアドレス
電話番号 任意
SNS 任意
支援プロジェクト
支援金額
支援プラン
支援日
支払い状態
リターン状況
タグ
メモ
お知らせ送信OK / NG
取得元 = Fund
```

DESK Contactsでは、Fund支援者だけでなく、Order購入者、Studio予約者、Event参加者なども横断的に管理できるようにします。

## 11. DESK収支との連携

Fundで発生した支援金は、DESKの収支へ集約します。

連携イメージ:

```text
Fund支援金
↓
DESK収支
↓
プロジェクト別売上 / 支援金として集計
```

将来的には、プロジェクトごとに以下も確認できるとよいです。

```text
目標金額
集まった金額
経費
利益 / 残額
リターン原価
```

## 12. Orderとの連携

Fundのリターン提供は、Orderの仕組みと相性が良いです。

例:

```text
支援者がリターンを選ぶ
↓
Fundに支援記録が作られる
↓
必要に応じてOrder側にリターン発送 / 納品タスクができる
↓
納品状況を管理する
```

リターンが物販、制作物、サービス提供の場合、Orderのステータス管理や納品管理を流用できます。

## 13. Storyとの連携

Fundで作ったプロジェクトは、Storyに活動記録として表示できるとよいです。

例:

```text
新作制作プロジェクトを公開しました
展示会出展プロジェクトが達成しました
支援者◯名に応援いただきました
活動報告を更新しました
```

Storyでは、細かい金額よりも、活動の実績やストーリーとして見せます。

## 14. Item Studioとの連携

Fundで制作する商品がある場合、Item Studioと接続できます。

例:

```text
Fundで新作制作プロジェクトを立てる
↓
完成した商品をItem Studioに登録
↓
在庫 / 販売 / 写真 / 出品管理へつなげる
```

先行予約型のプロジェクトでは、Item Studioとの相性が特に良いです。

## 15. Fundの強み

Fundの強みは、単体のクラウドファンディングページではなく、Mikke OS内の活動、顧客、収支、リターン管理につながることです。

通常のクラウドファンディング:

```text
ページを出す
支援を集める
終わる
```

Fund:

```text
ページを作る
支援を集める
支援者がDESK Contactsに残る
支援金がDESK収支に残る
リターンがOrderへつながる
完成物がItem Studioへつながる
活動実績がStoryへ残る
```

支援後の関係性と活動記録が残ることが、Fundの価値です。

## 16. 今は実装しない

Fundは今すぐ実装しません。

現在はMarketNote MVPを優先します。ただし、Order再構築やDESK Contacts構想と強く関係するため、今のうちに構想として保存します。

今後のOrder設計時に、Fundへ派生しやすい構造を意識します。
