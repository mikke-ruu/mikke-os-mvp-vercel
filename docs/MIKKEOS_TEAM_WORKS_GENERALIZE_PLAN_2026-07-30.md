## 0. 背景（あゆみ要望 2026-07-30 実機確認後）

> 1. ホーム: 混合の時はすべての予定を見れるタブもあったほうがいい
> 2. スケジュール管理: 混合の時スケジュール全体も統一感あった方がいい
> 3. プロジェクト管理: プロジェクトが上、新規追加が下が良い。統一感も揃えて
> 4. 納品型詳細: 概要にカレンダーを入れて、運営型のようにして
> 5. 工程ページ: 新規追加を畳んで。下まで見に行くの大変
> 6. 概要にカレンダーがあるなら、スケジュールタブはカレンダー無しで、工程とスケジュールは一緒で
> 7. ポータル側がどんな画面になっているか、何が反映されているかのビューが欲しい
> 8. 納品型にもメッセージ機能が欲しい
> 9. 運営型がアリサの日本語レッスンに寄っている。名簿を使わない業者もいるし、
>    ポータル側のレッスン画面や出席もいらない業者もいる。ポータル設定でON/OFFや
>    カスタムできるようにして、**アリサに実装した機能は崩さず**いろんな企業が使えるように

**大原則（継承）: アリサの組織のプロジェクトは、設定を変えない限り表示・動作が一切変わらない。**
機能ON/OFFは「null＝全部ON＝現状」のパターン（label_settings / operation_settings と同じ作法）。
ただし今回は、あゆみの明示要望による**全組織共通の意図的なレイアウト変更**が2つある:
- プロジェクト管理ページの並び替え（一覧を上・新規作成を下・運営型フォームを畳む）→ J-3
- スケジュール管理の時系列統合 → J-2
これらはアリサ画面にも見た目の変化として現れる（機能・データは不変）。

## 2. Phase J: ビューの統合と整列

### J-1. ホームに「すべて」タブ

- タブを `すべて / 運営 / 納品` の3つにする（両タイプある組織のみ。片方だけの組織は現状どおりタブ無し）。
- クエリは `?home=all|ops|delivery`。**初期表示は「すべて」**。
- **★「すべて」は"全部盛り"ではなく"混合スケジュールを一目で見る軽い画面"にする**
  （あゆみ確認 2026-07-30。当初の「運営タブの全セクション＋納品を足す」は破棄）。
  置くのは次の4つだけ:
  1. カレンダー（運営コマ＋納品期日を合成）＋右レールの FINANCE / MESSAGES
  2. カレンダー下のプロジェクトリンク（Phase Gの既存。ここから各プロジェクトへ入って予定を組む導線）
  3. TODAY
  4. NEEDS ATTENTION（**1セクションに統合**。中で運営ぶん→納品ぶんの順に並べ、
     区切り線の下に「今後の予定」を**運営コマと納品期日を混ぜた時系列1本**で出す）
  - **希望シフトパネルは「すべて」には置かない**（「運営」タブのみ）。
    狙いは「空いている日がひと目で分かる／予定を組めると分かる」こと。
- 「運営」タブ = 現状の運営ダッシュボード（希望シフトを含む）。
  「納品」タブ = 現状の納品ダッシュボード。どちらもPhase Gのまま。

**カレンダー合成の実装**: `TeamWorksMonthCalendar` に汎用スロット props を追加する
（統一計画の実装メモで予告済みの方式）:

```ts
extraItems?: { dateKey: string; label: string; bg: string; fg: string; dotColor?: string; href?: string }[];
```

- 運営コマのチップの後ろに描画。セル内の合計表示数は今と同じ最大2＋`+n`。
- 納品側は `loadDeliveryCalendarTasks` → `buildDeliveryCalendarItems` → 既存の色規則
  （itemTone相当）で extraItems に変換。
- **★ラベルにプロジェクト名を前置してはいけない（モック検証で判明・2026-07-30）。**
  カレンダーのマスは実測で約96px（チップの実効幅82px）しかなく、プロジェクト名を
  前置すると必要幅が234〜342pxになり、16チップ中10チップが「mik…」のように
  潰れて意味を成さなかった。**当初計画の「プロジェクト名を前置」は破棄する。**
  - ラベルは `提出 {工程名}` / `完了 {工程名}` / `提出・完了 {工程名}`。
    意味のある語を必ず先頭に置き、末尾が切れても種別だけは読めるようにする
    （この形なら最小でも7文字は見える）。
  - プロジェクトの区別は**チップ左端の小さな丸（プロジェクト識別色）**で示す。
    これは既存 `ClientMonthCalendar` の `projectDotColors` / `showProjectDot`
    と同じ作法。凡例とカレンダー下のプロジェクトリンクも同じ色を使って対応づける。
  - 納品型プロジェクト詳細内のカレンダー（1プロジェクトのみ）では丸を出さない。
- 凡例に「提出期日(PINK)・完了期日(BLUE)・期限超過(ORANGE)・完了(GREEN)」＋
  納品型プロジェクトの識別色を追加（extraItemsが空のとき＝アリサでは凡例も出さない）。
- チップの href はプロジェクト詳細 `?tab=tasks` へ。

**アリサ安全**: extraItems未指定なら描画・凡例とも完全に現状どおり。
タブ自体が出るのは両タイプある組織だけ。

### J-2. スケジュール管理を時系列1本に統合

- 「納品型の期日」独立ブロックを廃止し、**日付グループの中に運営コマと納品期日を混ぜる**。
- 納品期日の行は既存の行スタイルを踏襲しつつ、種別が分かるようにする:
  - 運営コマ: 現状のまま（時刻・担当・プロジェクト色バー）
  - 納品期日: 日付ピルの代わりに「提出期日/完了期日/提出・完了期日」バッジ（色はJ-1と同じ規則）＋プロジェクト名

- **これはアリサ画面にも出る意図的変更**（納品型0件なら実質変化なしだが、コード経路は共通化される）。

### J-4. 納品型詳細の再編（要望④⑤⑥）

タブ構成の変更:

```
現在: 概要 / 工程 / スケジュール / 成果物 / メンバー / プロジェクト設定
変更: 概要 / 工程 / 成果物 / メンバー / メッセージ(K-1) / プロジェクト設定
```

### J-5. 納品型に「資料」タブを新設（あゆみ要望 2026-07-30）

> 「納品型にもマニュアル（資料）を入れて共有できるところが欲しい。成果物前のファイル・URLとか
> スタッフも閲覧できるようにしておきたい」

- 納品型詳細に **「資料」タブ**を追加（タブ順: 概要／工程／**資料**／成果物／メンバー／

- 運営型の「マニュアル」に相当するものを、納品型では**資料**という名前で持つ。
  成果物（提出して承認を受けるもの）とは別物なので、**成果物のテーブルとは混ぜない**。
- 1件ごとに持つ情報: タイトル／種類（ファイル or URL）／関連づける工程（任意）／
  **見せる相手**（本部だけ ／ 本部とスタッフ ／ 本部・スタッフ・クライアント全員）。

  ファイル実体は成果物と同じ Storage の作法（`source_local_id` キー）に合わせる。

## 4. Phase L: 機能のON/OFF（運営型の汎用化・本命）

### L-1. データ設計

新カラム: `team_works_projects.feature_settings jsonb`（nullable・DEFAULTなし。migration 1本）

```ts
type TeamWorksFeatureSettings = {
  roster: boolean;      // 名簿（参加者・グループ）
  attendance: boolean;  // 出席（コマの名簿・出席記録）
  shifts: boolean;      // 希望シフト（パートナーの提出・本部承認）
  reports: boolean;     // 報告
  manuals: boolean;     // マニュアル
  lessons: boolean;     // ポータルのレッスン画面（コマ表示・Zoom）
};
// null → 全てtrue ＝ 現状のアリサと完全に同じ
```

- `lib/team-works-feature-settings.ts` を labels / operation-settings と同じ構造で新規作成
  （DEFAULT / resolve / load / update）。
- attendance は roster に依存（roster=false なら attendance も強制false）。
  依存関係はresolve関数内で吸収し、UIでは「名簿をOFFにすると出席もOFFになります」と表示。

### L-2. 効かせる場所

| 機能 | OFFのとき本部側 | OFFのときポータル側 |
|---|---|---|
| roster | 「名簿」タブ非表示。概要の対象者カード非表示 | クライアントの名簿系表示なし |
| attendance | コマ詳細の出席（名簿ビルダー）非表示 | パートナーの出席操作なし |
| shifts | 該当プロジェクトのシフト系UI非表示 | パートナーの希望シフト提出パネル非表示 |
| reports | 「報告」タブ非表示 | 報告の閲覧/提出なし |
| manuals | 「マニュアル」タブ非表示 | マニュアル閲覧なし |
| lessons | （本部のスケジュールは常時表示） | クライアント/パートナーのレッスンカレンダー・Zoom表示なし |

- タブの出し分けは `buildTabs` に settings を渡してフィルタするだけ（タブ内部は不変更）。
- **ホームの希望シフトパネル（組織横断）**: 運営型プロジェクト全てで shifts=false のときだけ
  非表示。1つでもtrue（またはnull）があれば現状どおり表示。実装時に
  `loadStaffPartnerShifts` の取得単位（組織/月）を確認してから出し分けを決めること。
- **RLSは変えない**（既存の注記どおり「認可はこの設定とは独立」）。これは表示の設定であって
  権限の設定ではない、という原則を守る。

### L-3. 設定UI

- 運営型「ポータル設定」タブを **「機能とポータルの設定」** に改名（タブIDは `portal` のまま。
  変えるとブックマーク・既存リンクが切れる）。
- 既存のチェックリストの上に「この事業で使う機能」グループを追加し、L-1の6項目を置く。
- 各項目に1行説明（例: 名簿「生徒・参加者の一覧とグループ分け。使わない業種はOFF」）。
- **★各項目に「誰のどの画面に出るか」を必ず文字で明記する**

## 4.5 さらに先のアイデア（Fable提案・2026-07-30。着手は未定）

あゆみ「他にこんな機能があると良いなどアイデアあったら教えて」への回答。
**この計画のスコープ外**。優先度順。どれもアリサの現行動作を壊さずに足せる。

1. **運営型のテンプレート化** ★一番効くと思う
   工程テンプレートは納品型にしかない。運営型にも「週次パターン＋名簿の枠＋

   一気に軽くなる。アリサが校を増やすとき／他社が同じ業態で使うときに直接効く。
2. **「この人が今どれだけ抱えているか」ビュー**
   スタッフ管理に、担当コマ数・担当工程数・期限超過数を1行で出す。
   今は誰に振れるか分からないまま担当を決めている。
3. **クライアント向けの進捗共有リンク（ログイン不要）**
   納品型で「今ここまで進んでいます」を読み取り専用URLで渡せる。
   ポータルにログインしてもらうハードルが高い相手向け。RLSは変えず、
   署名付きの公開ビューを別に用意する形にすれば安全。
4. **請求・報酬の復活**（前計画 §3.5-1 の続き）
   `TeamWorksProjectFinance` / `PayoutsTab` / `InvoicesTab` は実装済みだが未配線。
   工程・コマに単価を持たせればホームのFINANCEカードが初めて生きる。
5. **ふりかえりと見積り精度**
   終わった案件を実績として残し、納品型の `standard_days`（既存列）を実績から
   更新する。回数を重ねるほど逆算配置が正確になる。
6. **モバイルの「今日やること」1画面**
   スタッフが現場でスマホで見る前提の、今日の担当＋必要な資料＋報告だけの画面。
   既存の下部ナビ資産が使える。
